# 위젯 최종 구성과 적용 순서

## 구현한 내용
- 그린·블랙·스카이블루 / 스카이블루 학원 패널 #286599.
- 학원 일정 3열, 3·6·9개 선택. 학교 일정 세로 스크롤, 스크롤바 숨김.
- 오늘 일정: 12dp 빨간 알람 아이콘. 글꼴·글자 색상 유지.
- 노션 학원명 그대로 표시, TEEN은 작은 십자가.
- 과목 라벨 58dp, 좌우 패딩 0, 둥근 모서리. 노션 과목 색상 연동.
- 제목·날짜 길이 분리, 제목은 말줄임, 학교 날짜는 제목보다 1sp 작게.
- 위젯 제목은 학생 관리표의 ‘위젯 제목’. 비면 ‘학생 이름 Fighting’.
- 학원 DB가 없는 학생은 상단에 ‘시작 전 / 진행 중 / 오늘 마감’ 요약.
- 알림 권한·실제 알람 기능 없음. 빨간 아이콘은 오늘 일정 표시에만 사용.

## 노션 위젯관리
- 이름 옆 ‘연결 상태’: 확인 전(회색), 정상(초록), 허용치 초과(빨강).
- ‘허용 기기 수’ 기본 3. 0은 신규 연결 차단. 정수 0~100.
- ‘연결 기기 수’는 앱 설치 연결의 수. 같은 기기에 위젯을 여러 개 추가해도 연결은 하나.
- 기존 연결로 다시 연결/새로고침하면 기기 수가 늘지 않음.
- 앱 삭제 후 재설치는 새 연결로 간주. 기존 자리가 차 있으면 관리자가 연결을 정리.
- ‘최근 초과 일시 / 초과 시도 수 / 연결 기기 목록’은 서버 갱신.
- 잘못된 코드는 어느 학생인지 확인할 수 없어 학생별 초과 기록에 포함하지 않음.
- 허용치를 늘리면 다음 요청에서 정상 여부 재평가. 차단된 학생은 다시 연결.
- ‘위젯 연결 모두 해제’ 체크: 다음 연결/새로고침에서 처리 후 체크 해제. 웹 로그인에는 영향 없음.
- 연결코드 변경/연결 활성화 해제 시 기존 위젯 조회 차단.
- 기기 이름은 식별 편의를 위한 값이며 하드웨어 신원 인증은 아님.
- 노션 행 전체 배경색 자동 설정은 하지 않음. 이름 옆 색상 상태로 확인.
- 관리 수치는 실시간 푸시가 아니라 위젯 연결·새로고침 요청 때 갱신. 노션 쓰기가 실패해도 기기 제한 자체는 유지하고 다음 요청에서 다시 기록.

## Cloudflare 서버 반영 (필수)
worker.mjs 파일만 교체해서는 새 기기 제한 기능이 동작하지 않습니다.
새 Durable Object 연결 STUDENT_WIDGETS / 클래스 StudentWidgetDevices와 SQLite migration student-widgets-v1이 필요합니다.
설정 전 새 위젯 연결은 503으로 차단하여 제한 없이 연결되는 것을 방지합니다.

1. 기존 Worker의 환경변수·Secrets·RIVER_KV namespace ID를 보존합니다.
2. river/server/wrangler.toml에 기존 RIVER_KV 바인딩을 실제 namespace ID로 추가합니다.
   이미 서버를 운영 중이면 임의의 새 KV 저장소로 바꾸지 않습니다.
3. 현재 코드·설정으로 해당 Worker를 Wrangler 배포합니다.
   wrangler.toml에는 STUDENT_WIDGETS 바인딩과 new_sqlite_classes migration이 들어 있습니다.
   기존 migration이 따로 있다면 기존 항목을 보존하고 추가합니다.
4. 배포 후 최강 코드로 연결 → 관리표의 연결 기기 수 확인.
5. 3대 연결 후 4번째 연결 차단과 빨간 상태 확인 → 허용치를 4로 올려 재연결 확인.
6. 제목 변경 및 학원 DB가 없는 테스트 학생을 각각 확인합니다.

기존 관리 이전 토큰은 첫 확인 때 가져옵니다. 이미 3대보다 많은 기존 연결이 있으면 숨기지 않고 초과로 표시하며 신규 연결을 막습니다.
기존 관리 이전 기록은 KV 가시성에 따라 첫 확인에 늦게 나타날 수 있습니다.
새 관리 기능을 통한 신규 연결은 학생별 Durable Object에서 직렬 처리합니다.
토큰은 기존 정책대로 최초 연결 후 90일 만료입니다.

참고: https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/

## APK 서명 (최초 1회)
- SIGNING.md와 scripts/setup-signing.ps1 참고.
- GitHub에 RIVER_SIGNING_KEY_B64 / RIVER_SIGNING_PASSWORD / RIVER_SIGNING_ALIAS / RIVER_SIGNING_SHA256 등록.
- 개인 서명키/비밀번호는 공개 저장소에 넣지 않습니다.
- 이 설정 전에는 검사·서명 전 빌드만 가능하고 설치용 APK를 배포하지 않습니다.
- 기존 debug 서명 앱에서 release 서명 앱으로는 같은 앱으로 덮어쓸 수 없습니다. 최초 전환 뒤부터 동일 키로 업데이트합니다.
- 버전 1.23은 아직 공개 설치본이 없을 때만 사용합니다. 공개된 버전의 APK는 덮어쓰지 않습니다.
- 서명 APK가 실제 공개된 뒤 river/widget-release.json을 ready:true와 검증된 GitHub Release URL로 바꾸면 웹 상단에서 다운로드가 활성화됩니다.
