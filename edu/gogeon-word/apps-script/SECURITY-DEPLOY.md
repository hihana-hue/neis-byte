# 학습 서버 보안 수정 적용

이 수정은 GitHub에 저장하는 것만으로 운영 Apps Script에 적용되지 않습니다.
기존 학습 서버 프로젝트에 아래 파일을 반영하고 **기존 배포를 새 버전으로 업데이트**해야 합니다.

## 교체할 파일

- `Code.gs`
- `DeviceManagement.gs`
- `Permissions.gs`
- `ExamRecords.gs`
- `InterviewGyodae.gs`

`InterviewGyodae.gs`에 운영자가 입력한 시트 ID가 있다면 그 값은 보존하세요.
해당 파일은 기존 함수명 `setupGyodaeSheet`를 `setupGyodaeSheet_`로 바꾸고 안내 문구만 함께 바꿔도 됩니다.
스크립트 속성, 회원 시트, PIN, 이용 권한 체크박스, 등록 기기, 기존 세션은 유지합니다.
설정 초기화 함수를 실행할 필요가 없습니다.

## 변경 내용

- 설정용 함수 네 개의 이름 끝에 `_`를 붙여 브라우저의 `google.script.run` 호출을 차단했습니다.
- 내부 로그인도 `login_`로 비공개 처리하고 앱 지정·권한 검사를 필수로 했습니다.
- 기존 저장 함수 `recordProgress`, `saveLearning`, `saveEconomy`, `saveExam`은 공통 `mariSave`를 거칩니다.
- 학습 상태를 쓰기 전에 세션과 앱별 권한을 검사합니다. 한문 신호도 같은 검사를 합니다.

## 배포

1. 기존 학습 서버 프로젝트에서 위 파일을 교체하고 저장합니다.
2. **배포 → 배포 관리 → 기존 웹앱 배포 편집 → 버전: 새 버전 → 배포**를 선택합니다.
3. 기존 실행 사용자·접근 대상·배포 URL은 유지합니다. 새 URL을 만들거나 공개 범위를 넓힐 필요가 없습니다.

## 확인 기준

- 허용된 계정: 고전·경제어휘 로그인, 학습 완료·별표 저장, 재접속 복원 정상.
- 허용된 계정: 한문·교대면접 로그인 및 접속 기록 정상.
- 앱 권한이 없는 계정: 해당 앱 로그인·저장 모두 거절.
- 기존 세션에서 앱 권한을 해제한 계정: 다음 저장 요청 거절, 기존 학습 상태 보존.
- 만료·해제된 세션: 저장 거절.
- 운영 서버에 위 버전이 배포되었는지 확인한 뒤 적용 완료로 기록합니다.

로컬 회귀 테스트: 저장소 루트에서 `node tests/apps-script-security.test.mjs`.
이 테스트는 Apps Script 호출 경계와 저장 로직을 모의 환경에서 검사하며, 운영 배포 확인을 대신하지 않습니다.
